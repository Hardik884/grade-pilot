## Slide 2 — IDEA TITLE

**Grade Change Intelligence — predicting basis-weight breaches the operator cannot yet see**

*The problem*
- Grade changes ramp stock, filler, steam and speed together; desynchronised ramps push basis weight outside its ±2.5% band
- Every off-spec second at ~1000 m/min on a 6.4 m trim becomes broke

*The insight the system is built on*
- The QCS scanner reading is **41.4 s old** (median) — 7.2 s transport + 33.5 s traverse and hold
- A rule watching the displayed deviation reacts to sheet that no longer exists
- We run the mass balance on **current setpoints**, reading the sheet already at the headbox

*Why that is not extrapolation*
- Inside the measurement lag the loop has no information and cannot act
- The breach is already committed to the sheet — it is arithmetic, not a trend fit

*Result*
- Naive baseline catches **3 of 23** real breaches; this system catches **18 of 23**

*Mapped to the five stated challenges*
- High-loss grade changes → breach called 90 s in; broke tonnage quantified — **addressed**
- Operator explanation gap → evidence card, five weighted sources, validated narration — **addressed**
- Many interacting variables → recipe limits and actuator rates enforced; basis weight predicted, other quality loops enter as context — **partial**
- Automation that does not learn → retrieval over similar past transitions + learned residual; operator feedback captured, retraining not yet closed — **partial**
- Site data underused → QCS series and alarm history ingested; DCS historian, MIS and scanner diagnostics are roadmap — **partial**

## Slide 3 — TECHNICAL APPROACH

*Gray-box, physics first*
- Mass balance is not fitted — it is the relation the mill obeys
- Learned residual (gradient boosting) corrects only what 90 s of data cannot identify
- Contribution split **67.4% physics / 32.6% model**, asserted on every run

*Stack*
- Python 3.11, NumPy/pandas/SciPy, scikit-learn, Flask + static frontend
- 300-episode physics simulator; 90 tests; six-rule plausibility gate on all generated data

*Pipeline*
- Simulator → episodes → 90 s feature window → physics projection → residual → constrained advisor → evidence card → dashboard

*Lagged causal discovery, not a correlation heatmap*
- Discovered lags: speed 40 s, filler 40 s, steam 80 s, thick stock 80 s, consistency 35 s
- Matches the simulator's planted structure — never given to the ranking code
- Raw level correlations sit at **0.35–0.97**: everything looks connected, ordering is useless

*Safety, structurally*
- Constraint filter runs **before** scoring, so an unsafe setpoint is never a candidate
- Advisory only — never writes a setpoint

## Slide 4 — FEASIBILITY AND VIABILITY

*Measured, from 90 s of each transition (60 held-out episodes, 23 real breaches)*

| Model | Accuracy | Precision | Recall |
|---|---|---|---|
| Naive (deviation > 1.5%) | 0.650 | 0.750 | 0.130 |
| Physics only | 0.700 | 0.778 | 0.304 |
| Gray-box | 0.783 | 0.692 | 0.783 |

- Physics alone **triples** naive recall with zero learned parameters
- Max-deviation MAE improves 1.163% → 0.910%

*Why recall is the metric*
- False negative = broke on the reel; false positive = an advisory the operator dismisses
- Naive rule has *better* precision (0.750) and is useless — it finds 3 of 23

*Risks, stated*
- Validated on synthetic physics-based data — no real mill data was provided
- 60-episode test set: one episode moves recall by 0.043
- Stabilisation-time ranking is directional only — best p = 0.112, nothing significant at 0.05
- Constraint filter exercised by adversarial test, not yet by naturally binding limits

*Mitigations, and method we can show*
- Every episode passes a six-rule physical plausibility gate before use
- Thresholds calibrated on train only, never on test
- A 27-point tuning sweep and an alarm-feature addition both looked like wins on one split; 15-split repeats showed both were noise, and neither was claimed as a gain
